* [x] podman sandbox støtter ikke norsk tastatur i interaktiv modus — løst: `nb_NO.UTF-8` (og `en_US.UTF-8`) generert i bildet og injectert som `LANG`; overstyres med `SBX_LOCALE`.
* [x] Feat: Installer pi agent harness, og sett det opp likt som claude i begge sandboxene. Extensions til pi kommer senere. Se https://pi.dev/ — løst: `pi` (`@earendil-works/pi-coding-agent`) installeres i code-bildet og arves av pentest; `code/sbx-init.sh` avleder pi-modellkonfig (~/.pi/agent/models.json + settings.json) fra de samme env-varene som claude, så begge peker på samme modellserver/nøkkel/modell. Nøkkelen refereres kun som `${ANTHROPIC_API_KEY}`-interpolering (skrives aldri som tekst til disk); `PI_TELEMETRY=0`/`PI_SKIP_VERSION_CHECK=1` injiseres av sandboxen. Extensions: se punkt 6.
* [x] Feat: arg -p for å sette ekstern proxy. Firewall-logikk vil håndteres av den eksterne proxyen. Harrbjorns proxy trenger ikke startes. — løst: `-p host:port` (begge wrapperne) sender utgang gjennom en ekstern forward-proxy (f.eks. Burp): sesjonsnettverket lages uten `--internal`, harrbjorns egen proxy startes ikke i det hele tatt (bilde, policy, audit-logg), og containerens `HTTP(S)_PROXY` peker på den eksterne proxyen (loopback rewrites til `host.containers.internal`). Fail-closed: wrapperen TCP-prober `host:port` fra hosten før noe sesjonsressurs lages — svarer ingenting, hard feil og ingen sesjon (ingen fallback til egen proxy, åpen utgang eller no-proxy). `-a`/`-f`/`-H` har ingen effekt (advarsel); README-dokumentert som «Ekstern proxy» med isolasjonstrade-offen.
* [x] Feat: om burp proxy detekteres på porten, last ned og installer CA certificate fra http://<proxy>/cert i containeren — løst: `code/sbx-init.sh` (in-container init, kjører før kommandoen) henter `http://<proxy>/cert` direkte (curl `--noproxy`), parser det som X.509 (`openssl`, nå med i bildet; DER med PEM-fallback) og installerer det som combined-bundle (system-CAs + Burp CA) i `~/.sbx-ca-bundle.pem` (0600), eksportert som `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE`/`NODE_EXTRA_CA_CERTS`. Rootfs er read-only og agent-HOME agent-kontrollert mellom kjør, så bunken hentes på nytt hver kjør — CEn tillites aldri stå stasjonær, og agenten kan ikke plante en egen. Svarer porten med noe annet enn et parsebart sertifikat (non-Burp-proxy), skippes stillferdig; wrapperen har allerede bevist at porten svarer (fail-closed).
* [x] Extensions til pi bakede i docker-imaget (start: pi-subagents) — løst: `code/Dockerfile` tar `PI_EXTENSIONS` (mellomromskoddet liste av pi-pakkessilder, default `npm:pi-subagents`) og installerer dem ved build rett til `/usr/local/share/pi/agent/npm` via `PI_CODING_AGENT_DIR` (ingen relocate: cross-dir-rename på stacken feiler iblant med ENOENT). `/home/agent` er bindmount, så den bakede store-en (read-only rootfs) når aldri agent-HOME direkte: `code/sbx-init.sh` kopyerer den til `~/.pi/agent/npm` ved hver kjør og smelter inn i eksisterende store — både node_modules og storens `package.json` (pi kjører `npm install` mot storen og pruner node_modules-poster som ikke står i package.json). `packages`-listen i pi-settings.json smeltes på samme måte. Bildet er source of truth: baked extension agenten fjerner seedes på nytt ved neste kjør, lik modell-konfigen; agenten kan fortsatt `pi install`/`pi update` egne pakker i agent-HOME. Pentest-arven: `FROM harrbjorn/code:latest` tar med store-en automatisk.
